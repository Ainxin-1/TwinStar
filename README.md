# TwinStar ☄

Windows 桌面 P2P 文件传输工具。局域网直连、跨网 NAT 打洞、中继兜底，不设服务器、不需注册账号。

**下载**：[TwinStar v0.10.0（Windows x64，约 23 MB）](https://github.com/Ainxin-1/TwinStar/releases/download/v0.10.0/TwinStar-v0.10.0-win-x64.exe)

> **协议兼容性**：v0.10.1 更换了局域网发现的广播魔数（`TWINSTAR-DISC-v1`），v0.10.0 更换了传输协议标识（ALPN `twinstar/1`）。与 v0.9.x 及更早版本**互不相通**；v0.10.1 与 v0.10.0 之间传输可用（连接码），但局域网广播互相发现不了。传输双方建议使用相同版本。

## 工作方式

1. 双方打开程序，各自复制「我的连接码」发给对方（微信 / 邮件均可）
2. 对方粘贴连接码，拖入文件（或选择文件 / 文件夹）点「发送」
3. 接收方自动保存到接收目录（默认 `Downloads`，可更改）

连接码是设备公钥的 SHA-256 摘要（64 位十六进制字符），由 Ed25519 密钥对派生，同一设备跨重启保持不变。连接码也支持 `id@ip:port,...` 带地址写法——程序会把当前可直连的 UDP 地址（按公网 > 私网排序，最多 4 个）编进码里，对方粘贴后跳过地址发现直接拨号。

## 连接策略

按优先级依次尝试，实际使用哪条路在窗口顶栏实时显示（⚡ 直连 / 🔁 中继 + RTT）：

```
局域网直连（UDP 广播发现 / 连接码携带地址）
  → IPv4 UDP 打洞（iroh 后台持续进行，成功后从中继自动迁移到直连）
  → 中继兜底（iroh 官方免费公共中继）
```

与打洞相关的实现参数：

- **QUIC 流控窗口**：单流接收 16 MiB、发送 64 MiB（noq 默认值按 100ms RTT 设计，跨网链路上会把单流限到 ~5 MB/s）
- **发送前等待直连**：≥64 MB 等 4s，≥2 MB 等 2.5s，小文件不等待（直连与中继吞吐差距大，这点等待划算）
- **拨号超时**：单次 15s；首拨失败自动重试一次（首拨常卡在地址发现）
- **读写块**：1 MiB
- **已知干扰**：sing-box / Clash 等 TUN 虚拟网卡会接管 UDP 路由，打洞大概率失败——程序检测到会明确提示，此时仍可走中继传输

## 传输能力

- **批量传输**：多选文件 / 整个文件夹 / 拖拽一批，单批上限 5000 项、目录深度 32 层；接收侧按相对路径还原目录结构
- **并行分块**：≥16 MiB 的文件自动切 4 路并发流发送（高 RTT / 中继链路下吞吐显著更好）；接收端通过能力协商位应答，不支持时自动降级单流
- **断点续传**：接收写 `<文件名>.part`，sidecar `<文件名>.twinmeta` 记录内容指纹；指纹一致才续写（≤64 MiB 全文件 SHA-256，更大文件按 size+mtime+首尾 1 MiB 采样）
- **完整性校验**：接收完成后整文件 SHA-256 复算比对，不一致删除并报错
- **不覆盖已有文件**：重名自动另存 `xxx (1)`
- **路径防御**：接收侧对相对路径做规范化 + 越界检查，拒绝逃出接收目录
- **连接复用**：一次打洞多次传输（接收侧 120s 空闲后释放）；复用失效自动重连重发
- **进度与取消**：实时速率、已传 / 总量、预计剩余、批量时显示「第 i / N 个」，可中途取消

传输链路的加密封装由 iroh（QUIC / TLS 1.3）提供，身份即公钥——持有连接码即持有一个 32 字节 Ed25519 公钥，不暴露其他信息。

## 界面

| 页面 | 内容 |
|---|---|
| 传输 | 连接码、拖放发送、进度、通路徽章 |
| 设备 | 同网段设备列表（UDP 广播发现，携带直连地址，点「⚡ 发送」直接拨号） |
| 我的文件 | 已接收文件列表，支持打开 / 在资源管理器中定位（自动隐藏系统文件如 desktop.ini） |
| 活动日志 | 连接、通路、校验、文件操作全量留痕 |
| 网络 | 自检结果：UDP v4/v6 可用性、公网地址、NAT 类型（锥型 / 对称）、CGNAT 检测、各中继延迟，附可执行建议 |

局域网发现使用 UDP 广播（端口 39617，3s 间隔，12s 超时），**不是 mDNS**——同一网段内可用，跨网段请用连接码。

## 技术栈

| 层 | 选型 |
|---|---|
| GUI | Tauri 2（WebView2）+ 原生 HTML/CSS/JS，无前端框架 |
| 传输 | [iroh](https://github.com/n0-computer/iroh) 1.1（QUIC + NAT 打洞，按 EndpointId 拨号，无需信令服务器） |
| 语言 | Rust（edition 2021） |
| 平台 | Windows 10/11（需系统自带 WebView2 运行时） |

代码分层：

```
app/TwinStar-tauri/src-tauri/src/
  main.rs        Tauri 命令、事件、发送/接收编排、UI 状态
  net.rs         端点构建调参、连接码解析、通路判定、网络自检
  transfer.rs    传输协议：元数据协商 / 并行分块 / 续传 / 校验 / 会话复用
  disc.rs        局域网 UDP 广播发现
  core/          纯逻辑层（config / identity / limits / path，均已接入主链路）
```

## 构建

```bash
cd app/TwinStar-tauri/src-tauri
cargo build --release --features custom-protocol
```

产物：`target/release/twinstar.exe`（单文件绿色版）。

低内存机器建议 `-j 1` 并设 `CARGO_PROFILE_RELEASE_OPT_LEVEL=1`。

## 测试

```bash
cargo test --release
```

28 项单元 / 集成测试（含端到端传输、断点续传、并行分块、路径防御、连接码解析），另有 2 项真机网络自检 smoke 测试需真实网络环境，默认忽略：

```bash
cargo test smoke_real_network_diag -- --ignored --nocapture
```

## 已知限制

- 仅 Windows（Android / macOS 未做）
- 局域网发现依赖 UDP 广播，部分路由器隔离 AP（guest 网络）下不可用，用连接码不受影响
- TUN 模式代理（sing-box / Clash 等）会阻断打洞，只能走中继
- 对称型 NAT 打洞成功率低，自动走中继兜底
